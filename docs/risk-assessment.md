# Risk assessment

Project-specific risks for the Credit Risk Intelligence Platform (a coursework system, not a lending tool). Likelihood and impact are scored
**L**ow / **M**edium / **H**igh for *this* project. "Evidence" names what exists in the repository now; items marked **not yet run** are
implemented in code but have not been exercised against the real environment.

| # | Risk | Likelihood | Impact | Mitigation (implemented) | Evidence |
|---|---|---|---|---|---|
| R1 | **Unfair outcomes across groups.** The data (Taiwan, 2005) carries gender, age and marital-status patterns; a model can approve groups at different rates even when it never sees those attributes | H | H | Sensitive attributes (`SEX`, `MARRIAGE`, `AGE`) are **not** model inputs and are not accepted by the API; group metrics (approval rate, TPR, FPR, AUC) are computed per group on the test split; a challenger is rejected if any gap grows by more than 0.02 versus the champion; the UI and API say it is not a real lending decision | [fairness.md](fairness.md), `reports/fairness.json`, `params.yaml` → `promotion`, `src/models/promote.py`, [model-card.md](model-card.md) |
| R2 | **Score misread as a probability / model used for real decisions.** The champion's output is a ranking score (mean 0.40 vs 22 % real defaults) | H | H | The API returns `risk_score` and `score_type: uncalibrated_risk_score`, never `probability`; every response and the UI carry the disclaimer; the UI shows a band, not a percentage | [serving.md](serving.md) ("About the score"), [reviews/phase-2-review.md](reviews/phase-2-review.md) finding 1, API tests |
| R3 | **Data drift silently degrades the model.** Customers change (economic shock); the model keeps scoring as if nothing happened | M | H | Prediction log → drift monitor (PSI per feature, share ≥ 30 % alerts) and live AUC/recall; Prometheus rules + Alertmanager; `drift_watch_dag` starts `retrain_dag`; a retrained model only replaces the champion after the predefined comparison **and** a human approval; rollback path exists | [promotion-rollback.md](promotion-rollback.md), [evidence/phase-8/](evidence/phase-8/README.md). Drift and labels are **simulated** |
| R4 | **Credential leak** (API key, DagsHub/MLflow token, AWS keys) in git, images or logs | M | H | No secrets in git: pre-commit (gitleaks, private-key check) and CI gitleaks on **full history** (a narrow, tested exception only for Kubernetes secret *names*); secrets come from AWS Secrets Manager / Kubernetes Secret / env at run time; the deploy uses **OIDC**, not stored AWS keys (once the provider can be created, see below); the frontend never receives the API key; logs carry no payloads or keys | [security.md](security.md), [evidence/phase-0/](evidence/phase-0/precommit_blocks_secret.log), `.gitleaks.toml`, CI, [evidence/phase-9/](evidence/phase-9/README.md) |
| R5 | **Cloud cost overrun / forgotten resources** | M | M | Smallest Fargate size, one task, no NAT gateway or load balancer; a project budget exists (to be re-confirmed before deploying); the whole AWS footprint is two CloudFormation stacks removed by `teardown.sh`, which then lists what is left; costs estimated in the deployment doc | [aws-deployment.md](aws-deployment.md) (cost, teardown). **Not yet run** |
| R6 | **Public endpoint abuse or eavesdropping.** The API is reachable over the internet; there is no TLS terminator in the cheap design | M | M | Security group admits one CIDR; API key (40 random characters, compared in constant time) on every business endpoint; request size limit (1 MB) and batch limit (100); per-client rate limit (600/min, enabled in the AWS task and the prod Compose file); non-root read-only containers; Trivy/pip-audit/bandit in CI. **Accepted:** HTTP only (documented; use an ALB with TLS for anything real) | `src/serving/` tests, [aws-deployment.md](aws-deployment.md) "Known limits", [security.md](security.md) |
| R7 | **A bad model or image reaches production** (regression, poisoned retrain, broken build) | M | H | CI blocks merges (tests, lint, scanners, image scan); the deploy refuses a model whose gate failed; deployment is gated by a required reviewer; smoke test after deploy with automatic rollback; the retrain DAG never promotes by itself; the champion alias moves only after a successful, smoke-tested deployment | `deploy.yml`, [promotion-rollback.md](promotion-rollback.md), `pipelines/tests/` |
| R8 | **Overclaiming simulated results.** Drift, delayed labels and feature timestamps are simulated; a reader could mistake them for field evidence | M | M | Every doc, script, dashboard panel and status payload that uses them says "SIMULATED"; the live-performance panel is titled so | [promotion-rollback.md](promotion-rollback.md), `scripts/simulate_drift.py`, Grafana panel title |
| R9 | **Supply-chain compromise** (a malicious dependency, action or image) | L | H | Dependencies pinned and constrained by `requirements.lock.txt` / `package-lock.json`; GitHub Actions pinned to commit SHAs; pip-audit, npm audit and Trivy (HIGH/CRITICAL with a fix fail the build); runtime images drop build tools; model loading only from our own registry/DVC remote (documented unpickling risk) | CI, [security.md](security.md) accepted-risk table |
| R10 | **Personal data in monitoring data** (prediction log, reports) | L | M | Pseudonymised log (keyed hash of an optional customer id, no direct identifiers, no sensitive attributes); 30-day retention enforced in code and by an S3 lifecycle rule; the log is separate from the application log | `src/monitoring/prediction_log.py` + tests, `bootstrap.yaml` lifecycle rules |
| R11 | **Single point of failure** (one ECS task, one local node) | M | L | Acceptable for coursework: ECS replaces a failed task, the deployment circuit breaker and the smoke-test rollback protect releases; the Kubernetes demo shows multi-replica behaviour locally | [aws-deployment.md](aws-deployment.md), [kubernetes.md](kubernetes.md) |

## Open risks that need a decision
* **GitHub OIDC may be blocked by an organisation policy** (an SCP denies `iam:ListOpenIDConnectProviders`, recorded in `memory.md`). If creating the provider fails, the no-stored-keys design needs an allowed provider or an instructor-approved fallback ([aws-deployment.md](aws-deployment.md)).
* **No second reviewer is configured yet** for the `production` Environment; the approval gate is only as strong as the person approving.
* **Hard AWS spend limit** (AWS Settings → Billing) is unconfirmed; a budget alert only warns.
