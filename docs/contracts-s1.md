## 2. Stage interface (Live)
Every S1 stage is a module exposing `run(params: dict, smoke: bool) -> dict` plus a CLI built with `src.common.cli.stage_main`:

```
python -m src.<pkg>.<module> [--params params.yaml] [--smoke] [--log-level INFO]
```
`dvc repro`, Kubeflow components and Airflow tasks call this same entry point; nobody reimplements stage logic.

| Exit code | Meaning | Caller should |
|---|---|---|
| 0 | OK | continue |
| 1 | Error (crash, bad config, bad CLI usage, source unreachable, raw file missing) | retry per policy, then fail |
| 2 | Data validation failed | stop the DAG, **do not retry**, do not trigger Kubeflow (e.g. Airflow `AirflowFailException`) |
| 3 | Quality gate failed | stop, do **not** deploy |

`--smoke` = tiny/fast mode for CI and tests. It always uses **synthetic** data (`smoke.n_rows` rows) and reads/writes only under `data/smoke/`, so it can never overwrite DVC-tracked `data/raw` or `reports/`. Never used for real runs. Seeds are applied before `run` from `params.yaml: seed`.

## 3. Parameters (Live)
`params.yaml` is the single source of truth (seed, data source and paths, smoke settings, validation thresholds, split, sensitive columns, gate threshold, MLflow/registry names). It is validated on load; invalid files exit 1. Model hyperparameters live in `configs/model_params.yaml`. Only environment-variable **names** are committed (`configs/pipeline_config.yaml`, `data.s3_uri_env`). A relative `--params` path is resolved from the repository root, not the current directory.

Data sources (`data.source`): `uci` (download the official zip), `s3` (object named by the env var `RAW_DATA_S3_URI`, plain `s3://bucket/key`, `.csv`, `.xls` or `.zip`; credentials from the standard AWS chain or OIDC), `local` (`data.local_path`), `synthetic` (generated stand-in, demos and tests only).

**Raw CSV schema (Live).** Columns in this order: `ID`, `LIMIT_BAL`, `SEX`, `EDUCATION`, `MARRIAGE`, `AGE`, `PAY_1..PAY_6`, `BILL_AMT1..6`, `PAY_AMT1..6`, `default_next_month`. Only headers are normalised (UCI `PAY_0` becomes `PAY_1`; `default payment next month` becomes `default_next_month`); values are untouched. Integer-valued columns are int64. LF line endings, so hashes are identical on Windows and Linux.

**`reports/ingestion_report.json`:** `source` (`uci|s3|local|synthetic`), `synthetic` (bool), `rows`, `columns`, `sha256` (of the CSV), `file`.

**`reports/validation_report.json`:** `status` (`passed|failed`), `rows`, `columns`, `target_rate`, `errors[]` (`column`, `check`, `count`, `examples` max 3 offending values), `warnings[]` (`undocumented_codes` with counts per code, `duplicate_rows_excluding_id`). No timestamps, so it is deterministic. Hard failures: wrong/missing/extra columns, wrong types, nulls, duplicate IDs, values outside the domains/ranges in `params.yaml`, target not 0/1, target rate outside `[0.05, 0.60]`, fewer than `validation.min_rows` rows. The real data's undocumented codes (EDUCATION 0/5/6, MARRIAGE 0, PAY -2/0) are warnings only.

The UCI file has no row timestamps. Feast's `event_timestamp` and any "time-ordered" batches are **synthetic** and must be labelled simulated (rules.md §9). Anything built on `data.source: synthetic` must never be reported as a result: `synthetic: true` is in the ingestion report and becomes the MLflow tag `data_source` in C2.

## 5. DVC pipeline (Live, `dvc.yaml`)
`ingest` (`python -m src.data.ingestion`) -> `validate` (`python -m src.data.validation`); later `preprocess -> train -> evaluate`. One owner edits `dvc.yaml`; ask before changing it. Runbook, reproducibility demo and merge-conflict handling: `docs/dvc-runbook.md`. The DVC remote (S3 / DagsHub) is not configured yet and is Hashir's AWS item; `.dvc/config` deliberately holds no remote and no credentials.

**For the Airflow DAG:** `fetch_data` -> `python -m src.data.ingestion` (source `s3`) -> `python -m src.data.validation`; branch on the exit codes in section 2. The validation report in `reports/` is the artefact to attach to the run.

## 6. Model registry (Planned, C2/C3)
- Registered model: `credit-risk-default-model`. Promotion = moving an **alias**; MLflow stages and a `Production` alias are not used.
- `challenger`: newest candidate that passed the gate. `champion`: approved, currently deployed. Serving loads `models:/credit-risk-default-model@champion`.
- Python helpers in `src/models/registry.py`: register, set alias, load by alias, `passes_gate(metrics, params)`.

## 7. Required MLflow run tags and params (Planned, C2)
`git_commit_sha`, `dvc_data_hash` (the raw CSV hash from `dvc.lock`), `data_source` (from the ingestion report), `feast_repo_commit` (spec §12.1), `algorithm`, `seed`, `smoke` (true/false), plus metrics (ROC-AUC, PR-AUC, KS, recall/precision at threshold) and training duration. Tracking URI comes from `$MLFLOW_TRACKING_URI`.

## 8. Sensitive attributes (Live config, enforced from C2)
`SEX`, `MARRIAGE`, `AGE` are excluded from model inputs (`features.exclude_sensitive_from_model: true`) and used only for fairness reporting. They are not part of Feast training feature views.
